# Gia site — rules for every task

Static four-page site (no build step): index.html (Meet Gia), glo.html (Introducing GLO),
global-connections.html (Global Connections), how-glo-works.html (How GLO Works).

@README.md

## Before changing anything
1. Read the files relevant to the task before editing:
   - Any visual, layout, component or motion change: docs/GIA-SITE-DESIGN-SYSTEM.md
   - Any color change: docs/GLONARI_PULSE_COLORS.md (it overrides everything else for color)
   - Any copy or section change on a page: that page's wireframe in docs/wireframes/
2. For anything larger than a small fix, show a short plan and wait for my OK.
3. Change only what the task asks. Never change other pages or approved sections as a side effect.

## Project rules
- Header, mobile menu and footer are generated by tools/build-shell.py. Never edit the HTML
  between <!-- shell:... --> markers; edit the script and run `python3 tools/build-shell.py`.
- Shared styles go in css/components.css, page-only styles in css/pages/<page>.css.
  If a second page needs a page-only style, move it to components.css.
- Videos never loop: use video[data-play-once] (plays once per visit to the screen),
  muted, no audio track, with poster (first frame) and data-still (last frame).
  Pages using it must load js/components.js after js/site.js.
- Keep original media in assets/source/; optimized files in assets/video/ and assets/images/.
- All site copy, code comments and docs are in English.
- Content rules (GLO pages): no rate per GLO, no percentages or returns, no promises of income,
  liquidity, resale or appreciation; compensation only as one illustrative total per project.
  Options are always Use, Put it to work, Support, Transfer, in this order.

## After every change
- Check the browser console has no errors on the changed pages.
- If you changed rules, files or structure, update README.md and/or
  docs/GIA-SITE-DESIGN-SYSTEM.md in the same task.

## Reporting
- Do not take screenshots or produce visual reports unless I explicitly ask for them.
  I check the visual result myself in VS Code and the browser.
- Verify with lightweight checks instead (console errors, broken links, grep), not by rendering pages to images.
- Keep the final report short: what changed (files), anything I need to decide, nothing else.
  No long summaries, tables or step-by-step narration of the work.
